# Ancient Building / Ancient Town 长程任务验收评估

日期：2026-09-26。评估对象：`2497eee..22a1a1c`，主要成果提交为 `07236dd`、`22a1a1c`。

范围补充：评估开始时工作区干净；结束时发现 `AncientBuildingParameters.h`、`BuildingBuilder.h` 出现外部未提交修改。这些在途修改不属于本报告评估的已提交成果，本次未改动或回退它们。

**结论：可接收为城镇布局与渲染联通原型，不能按“高质量、多变体、支持中大型古代城镇”的最终成果验收。**

主要偏差是先扩大城镇规模，后用机位、补光和像素亮度修补展示效果；v2 要求优先完成的单体质量样板、结构约束和规模化交付能力没有形成闭环。局部迭代确实发生了，但迭代目标不足以覆盖最终需求。

## 3. 必须先修复的确定性问题

### 3.1 城市第二排房屋进入道路（阻断布局验收）

位置：`Game/addons/ancient_town/nodes/town_lots.gd:630`、`:642`。

北排第二排计算为 `z_n - depth_n/2 - 7 - depth_n2/2`，实际继续向北移动；南排第二排则继续向南移动。两者都与注释“街区内部一排”的意图相反。

北侧街区边界记为 B，margin=10，则第二排中心为 `B + 3 - depth_n2/2`。depth_n2 在 6.5–9.0 之间，所以中心已位于 B 外侧 0.25–1.5 个单位。这里恰是内部街道区域。加大退距、换机位或修路面颜色均不能消除该缺陷。

| 种子 | 总建筑 | 地面建筑中心位于道路内 | 民居被配置为无墙 / 民居总数 |
|---|---:|---:|---:|
| 42 | 408 | 80 | 317 / 330 |
| 7 | 405 | 80 | 322 / 339 |
| 123 | 404 | 80 | 320 / 330 |

检测将建筑中心变换到每条道路的局部坐标，判断其是否位于道路矩形内部，排除高于地面的城楼。这个指标尚未计算屋檐、台基和台阶侵占，因此不是全部相交数量。

修复应包括方向公式、街区边界和道路保留区约束。之后以实际烘焙包围范围或 footprint 验收，不能只对生成前的 width/depth 做估计，因为共享变体和后续 size_jitter 都可能改变最终范围。

### 3.2 变体共享会丢失墙体、开间、台阶等语义

位置：`Game/addons/ancient_building/nodes/ancient_building.gd:114–182`。

共享键只包含量化宽深、屋顶和材质预设，忽略 bays、walls、steps、fence、瓦参数和起翘参数。烘焙取该组第一个点的完整参数，因此后续点的不同要求不会落到网格。

探针中，同宽深/屋顶/材质但“3 开间、有墙、有台阶”和“1 开间、无墙、无台阶”的输入得到完全相同的键。第一项输入换顺序，还可能让整组建筑换外形。代码上方声称 bays 保持精确，与实际键定义不一致。

另外，量化宽深到 4.0 时直接终止收敛，并不保证满足 variant_count。9 屋顶 × 3 材质即有 27 个分类组合，设置 cap=24 仍超限。

修复原则：所有影响网格的离散语义进入规范化描述；连续参数先明确量化，再按规范化值烘焙；材质、实例色与几何共享分别处理。超过预算要报告原因或采用显式回退，不能静默丢弃墙体等要求。补点顺序打乱、只改开间/墙体、超预算等小型回归。

### 3.3 民居被当成开放亭台，材质风格被覆盖

位置：`town_lots.gd:170–172`，`ancient_building.gd:325–330`。

- `walls = level >= 3` 导致大量低等级民居不生成墙。它是截图中红柱开放空间大量重复的直接参数原因；上述数量统计指输入配置，实际共享后的网格还受 3.2 影响。
- 设置 material_style 后又无条件写入统一 stone/timber/plaster/tile 颜色，覆盖了茅草与土木预设的这些主要颜色；脊、斗拱等未覆盖字段仍可能保留差异，不能说所有风格完全相同。
- 当前茅草/土木主要是调色能力，没有因此生成不同构造的茅草屋与夯土民居。

需要用用途决定围护与入口，等级只控制尺度、结构规格和装饰强度。优先独立实现民居、临街商铺、院落正房/厢房，再保留亭、殿、门楼等公共建筑类型。颜色覆盖应具有明确的“使用预设 / 自定义覆盖”开关。

## 4. 影响最终观感的能力缺口

### 4.1 屋顶类型多，不等于建筑类型丰富

最终图的主要重复来自相近的柱网、台基、屋身比例和立面，而不只是屋顶类型。全城大量红柱高台、开放围护和类似栏杆，难以形成普通生活街区与重要公共建筑的层级。

建议按三层建立变化：

1. 用途原型：民居、商铺、作坊、客栈、院落、祠庙、亭、城门。
2. 空间与构造：开间深度、正厢房组合、前店后院、转角铺面、入口朝向、围墙和连廊。
3. 外观：屋顶、瓦色、木色、修缮差异、门窗、招牌与少量生活附属物。

先控制合乎用途的组合，再随机化。无需首轮实现全部原型，先交付足以组成一条街的四至六类。

### 4.2 单体精度升级被绕过

本轮未修改 C++ 几何生成，意味着连续屋面、质量与造型解耦、柱面法线、真实局部倒角、檐下结构、瓦片搭接等 v2 主线没有得到本轮实现证据。截图中的屋面重复条纹、较硬的轮廓和高度相似的构件语言仍然明显。

下一轮先完成一栋民居和一栋歇山公共建筑的质量样板，至少检查屋脊—坡面—转角—檐口的连续性、瓦片节奏、木构连接、门窗与墙体厚度、台阶和人物尺度。造型参数与细分/LOD 参数必须分离，不能用增大瓦片尺寸冒充性能优化。

允许关键斗拱、瓦当、脊饰等采用经审核的模块资源，由 PCG 负责尺寸、接口、放置和变体；所有细节都用通用程序基本体重新造一遍，不是本项目的必要目标。

### 4.3 城市仍是固定模板，缺少地块与院落层

城市固定 4×4 街区，市集固定 3×3，主要靠循环和坐标偏移布置。城市中心留出 2×2 街区，而主体宫院只占其中较小部分；普通街区也缺乏内部院落填充，造成鸟瞰的大面积空白。修复道路上的房屋后，需要重新组织街区内部，而不是单纯往空地加随机房子。

能力边界也没有与设置项匹配：城市街区和城墙多处以 Ex 同时控制 X/Z，独立 extent_z 无法完整控制矩形城市；小聚落的 extent 参数没有形成一致的尺度控制；城市 density 主要影响道具和树，固定建筑行列没有相应变化。

建议形成 `环境约束 → 路网 → 街坊 → 地块 → 院落 → 建筑 → 道具` 的可检查中间结果。每一步保留可视化和人工覆写入口。研究落地不必完整复刻论文，但应明确哪些是借鉴、哪些是自定简化。

已有城市论文强调局部约束、可控对称性和距离引导，CGA 论文具有明确的 scope、split/repeat 和上下文规则。当前代码可以说借鉴层级思想，不能仅凭 3×3 循环和实例化就认为这些方法已完整实现。混合不同地域、时代的规则也应作为明确的游戏美术设定，不包装成已验证的历史准确性。

### 4.4 NPR 调整过于围绕当前截图

市场图仍体现道具稀疏、建筑与摊位尺度层级突兀、地面缺乏空间归属。补光能改善可读性，不能生成商铺立面、生活细节或地表构成。

共享 shader 还加入 `abs(lw.y) < 0.1` 自动识别补光的分支（`ink_surface.gdshader:119`），实际未区分光源用途；接近水平的光无条件绕过墨色路径，零向量默认值也不能关闭这一分支。它对其他场景的影响尚未经过本次渲染回归，属于需要验证的共享材质风险。

改进应先分清瓦、木、石、墙、夯土的形体、色阶和笔触尺度，再统一日照、阴影和环境填充规则。保留有设计的水墨留白，但不能让留白代替道路边界、院落关系和地表接合。

## 5. 中大型地图能力尚未得到验证

当前 spawn_meshes 按 Mesh 资源聚合 MultiMesh，没有按空间街区细分这条交付路径。新增地图也没有接通建筑 LOD、持久化烘焙缓存、分块加载、碰撞与导航。已有框架可能具备部分基础节点，但不等于此场景已经使用并验收。

日志记录 MMI 和总实例数；未找到相应的目标机帧时间、三角形/显存、冷/热加载、移动穿城或战斗叠加预算报告。截图成功不能推导 60 FPS 或中大型规模达标，本次无头探针同样不能提供这类结论。

规模交付至少要验证：

- 三档 Mesh 表现，并保持轮廓、材质及结构语义稳定。
- 按空间块、变体、LOD 组织实例；烘焙结果可缓存和复用。
- 建筑入口、道路、院门与城门的连通性；碰撞和导航与最终几何一致。
- 目标机器、D3D12、分辨率、画质、构建类型固定，记录 CPU/GPU 帧时间 p50/p95/p99、峰值内存/显存、冷/热加载及最坏视角。
- 60 FPS 是完整游戏预算约束。先明确城镇可用预算，再加入角色、敌人和战斗特效验证余量。

## 7. 长程任务的验收方式需要调整

下一轮每个工作包都要求提交：原始缺陷、修改证据、固定种子、固定机位前后对比、自动数据检查、性能变化、仍未解决项。评审可以判不通过，不能只在“已完成”文档后追加新的截图说明。

应明确三道门：

1. 正确性：无非法相交，语义参数真正生效，点顺序变化不改变已定义建筑，随机结果可复现。
2. 质量：单体构造、居民用途和街道空间在项目实际镜头下成立；近景补充用于检查缺陷，不能仅用鸟瞰缩小问题。
3. 交付：目标机性能、加载、编辑体验、碰撞导航和局部再生成均有数据。

**下一轮最有价值的成果是“一条正确、精致、能走进去的古代街区，以及它的规模化方案”。通过后再复制到大城，才能让数量增长带来质量可控的内容增长。**
