# AncientBuilding 质量升级执行计划 v2

日期：2026-09-25。状态：研究与实施规划，尚未执行代码改动或性能测试。

目标：让现有 AncientBuilding 从批量建筑原型升级为适合水墨武侠 ARPG 的近景建筑生成器；同时保留可复现变体、PCG 实例化和远景运行效率。

本计划替代旧执行文档的实施顺序与验收口径，保留旧文档作为评审历史。依据为三篇本地论文原文转换稿、Hu 论文图 14/15，以及当前 C++ / GDScript 实现。下面标记为“工程方案”的内容不是论文原作者的结论；所有新增参数默认值均为初始调试值，不是建筑史标准或实测最优值。

转换稿存在公式、表格错位：H 式 6 的向量文字，Q 表 7 的列头、式 10 的范数表达及图 13 的指数说明不能仅凭 OCR 照抄。此次计划不依赖这些不明确的表达实现城市算法；进入对应阶段时需回查原 PDF 页面。

## 2. 对旧执行计划的关键修正

| 旧任务 | 问题 | v2 决定 |
|---|---|---|
| A1 把瓦宽归入网格质量 | 瓦宽改变建筑细部尺度 | 瓦长、瓦宽、搭接量属于构件尺寸；采样误差、截面边数属于质量 |
| A2 直接删除步架数对高度的影响 | 破坏旧场景默认比例；结构参数允许影响造型 | 保留 Legacy 计算模式；新增显式高度模式；只保证质量参数不改变目标造型 |
| A3 对旧折线中点递归二分 | 线性段中点弦高为零，加密不能得到更光滑的目标曲线 | 先定义连续屋面函数，再自适应采样 |
| A3 要求步架数 3/9 截图一致 | 混淆结构参数和精度；不同三角化与抗锯齿也无法保证截图零差 | 固定结构比较质量档，以曲面误差、接缝与关键点位置验收 |
| B1 使用边中点角输出柱法线 | 一面仍然只有一个方向，无法得到正确的跨面平滑 | 顶点角解析法线；考虑柱身收分造成的法线竖向分量 |
| B2/C2 用双顶点法线代替倒角 | 不会产生真实倒角轮廓、遮挡和接触阴影 | 可见棱边采用真实窄斜面；法线平滑只负责受光 |
| B3 每排末端加瓦当 | 混淆搭接边与檐口端部构件 | 瓦当/滴水仅布置在实际檐口；普通排生成搭接边 |
| B3 限定最多 48 排 | 强行少排可能形成空缺或改变真实瓦长 | 超预算切换表现档，不静默拉伸瓦片或截断覆盖 |
| B4 宣称现有正脊穿模已证实 | H 的用户反馈不能证明本项目所有屋型有同一缺陷 | 先建立大瓦宽/极端坡度复现；按实际问题修正 |
| C1 一垄一椽、固定飞椽高度 | 三篇文献没有给出通用施工尺寸规则 | 椽距独立，默认与瓦垄节奏协调；飞椽由檐口构造断面决定 |
| C3 直接以现有节点复刻回转柱础 | 当前扫掠位移不等于通用回转建模接口 | 复用纯 C++ 内核；柱础采用明确的半径-高度剖面回转函数 |
| D2 统一材质只增加两个 uniform | 不能让同一建筑内木、石、瓦、墙得到不同响应 | 首轮明确分四个材质槽；后续按实测决定是否合并着色器 |
| D2 瓦面 metallic=0.12 | 不是本文献结论，也不适合作为普通瓦的物理默认值 | 普通木/石/墙/瓦默认非金属；有金属装饰时另建类别 |
| D3 只测重复生成颜色一致 | 当前计数器方案本来就能重复生成一致；没有覆盖细分/LOD 变化 | 按语义构件 ID 比较不同采样、不同 LOD、局部修改的稳定性 |
| E 把输出构件列表放进 BuildingSpec | 混合输入规格和输出状态，影响缓存与并发边界 | 输入、骨架、构件记录、烘焙结果分开 |
| F 重檐=调用两次屋顶 | 缺少承托、上下檐关系、内部屋面开口和主体衔接 | 独立的屋顶层级任务；重檐与多楼层分别描述 |
| G 距离变化就重新 Generate | 破坏共享变体，带来运行时生成尖峰 | 编辑/烘焙阶段生成静态档位，运行时只选择档位 |
| G 直接要求 1/35 面数、固定 200/300m | 来自特定实验或旧计划假定，不是本项目预算 | 按目标机位、屏幕误差、GPU 与内存实测确定 |
| 验收允许近景 45 FPS | 降低了项目 60 FPS 目标 | 目标保持 60 FPS；超预算要记录和处理，不能作为合格条件 |

## 4. 目标数据流程

```text
Authoring Parameters + Preset + Stable Seed
                   ↓ resolve / validate / legacy conversion
ResolvedBuildingSpec（结构、造型、构件尺寸）
                   ↓
BuildingFrame（柱网、屋面域、脊/檐共享边界、楼层/屋顶层标识）
                   ↓
ComponentRecords（稳定 ID、局部坐标、材质类别、原型与尺寸）
                   ↓ + QualityProfile + 可选原型替换
BuildingBakeResult（各 LOD 的 Mesh、定位点、统计、缓存键）
                   ↓
单体预览 / 现有 mesh 资源流 / 后续空间分块建筑实例器
```

以上为拟新增内部结构。首轮仅建立屋面、稳定 ID 和烘焙结果需要的部分，不把整座建筑立即重写成通用图编辑器。现有 PCG 图继续负责上层流转；构件层级描述负责建筑内部依赖，两者不能互相替代。

必须固定的契约：

1. 相同结构、造型和构件尺寸，切换质量档不改变目标屋面、瓦片物理尺寸或构件定位点。
2. 屋面、望板、屋脊、瓦面、檐下构件引用同一套边界语义；实际偏移由厚度与构造层定义。
3. 构件 ID 由层、屋面/立面、开间、构件类型和物理排号等组成，不由顶点顺序或采样节点数决定。
4. 单体编辑器与 PCG 共用同一个参数解析入口；原有 `bake_mesh()` 保持返回 Mesh 的接口。
5. 输出 mesh 默认不可变；实例差异走实例数据或新的变体，不修改共享 Mesh 资源。

## 5. 实施阶段

顺序：P0 → P1 → P2 → P3 → P4，完成第一轮歇山样板；再做 P5 批量交付。P6 的替换/重檐、P7 的城市内容扩展分别立项，不是首轮必备条件。

### P0：建立可复现基线

**目的**：先确定当前实际输出、构建能力与缺陷，而不是等待外部样例才开始。

任务：

- 核实根目录 `SConstruct`、`Game/bin/abyss.gdextension`、自定义引擎二进制和扩展 API 一致。根目录 SConstruct 已汇集 `Source` 下代码并输出到 `Game/bin`；不按旧说明到 `godot-cpp` 内构建应用扩展。
- 构建环境可用后，从仓库根目录执行 `scons platform=windows target=template_debug arch=x86_64`；若使用 uv，先确认现有环境内 SCons 的启动方式。本计划阶段不安装依赖、不重编 DLL。
- 新建拟议目录 `Game/Develop/AncientBuildingQuality/`，生成歇山 11×7m 样板、九屋顶矩阵、40 个实例/4 个变体基准；外部样例作为后续补充。
- 固定随机种子、光照、材质、相机、分辨率、抗锯齿、渲染器和阴影设置。建立檐下、地面仰视、俯视三个截图机位及一条穿村运动路径。
- 输出总量及按部件统计：顶点/三角形、surface 数、生成时间、数组提交时间、缓存内存；记录 CPU/GPU 帧时间与可见实例数。
- 建立缺陷清单：正脊/翼角接合、大瓦宽、低/高坡度、集中式顶冠、卷棚两端檐口、覆盖率边界。

**验收门槛**：能够从保存的参数重建相同基线；区分“运行复现”“静态风险”“仅文献提到”。硬件、构建版本及测量设置齐全。

### P1：解耦参数并建立稳定屋面采样

**依据**：H §3.1、§4.2 和图 14/15；连续解析曲线、自适应算法、版本化为工程方案。

**改动位置**：`AncientBuildingParameters.h/.cpp`、`BuildingBuilder.h/.cpp`、`PolygonalBuilding.cpp`、`SplineSweep.h/.cpp`、`AncientBuilding.cpp`；拟新增 `RoofFrame.h/.cpp`。

**P1.1 兼容与参数**

- 保留 `rafter_courses` 作为结构输入。高度模式新增 `LegacyDerived` / `Explicit`；旧资源缺少新增字段时仍按 Legacy 解释。显式高度默认从旧资源当前计算值初始化，而不是写入一个统一常量。
- Legacy 保留旧折线定义；新版造型模式单独选择连续曲线。预设版本与生成器缓存版本分离。
- 独立柱身高度、柱顶标高与屋顶基准，避免混用“柱高”和“檐高”。添加可选开间宽度数组，默认仍为原均分；明间系数在奇数开间时可生成对称数组，偶数开间需定义双中间或保持均分。
- 瓦长/瓦宽/搭接长度、椽径/椽距属于尺寸层。质量层只包括曲面误差、最大边长、截面细分、细节档。

**P1.2 连续目标曲线**

当前举架比例从檐口 `a` 线性变化到屋脊 `b`。可以先用其积分建立连续母线，作为工程化 V2 默认：

```text
t ∈ [0,1]，檐口为 0，屋脊为 1
x(t) = HalfSpan × (1-t)
y(t) = H × [a×t + (b-a)×t²/2] / [(a+b)/2]
```

在 `a,b` 为合法正值时，该函数在旧均匀节点处可对应旧中点积分的高度，但节点之间由旧直线段变为曲线；这是造型模式升级，不能宣称与旧网格像素完全一致。异常输入应验证并给出可重复的回退。

后续需要艺术控制时添加三次 Bezier 模式，保留檐口、脊、收山转折等强制节点。卷棚圆弧、盔顶鼓出、翼角变形均有自己的连续取值定义；不以增加 `rafter_courses` 模拟精度。

**P1.3 采样与边界**

- 在变形后的三维曲线上评估误差；用区间 1/4、1/2、3/4 点到弦的距离和切向变化判断是否拆分，避免只取中点漏掉 S 形弯曲。
- 先试近景误差 0.005m、最大段长 0.5m、最大递归深度 8；这些是调试起点。达到深度或面数上限时输出诊断，不能宣称仍满足误差。
- 全局边界表保存屋脊/檐口/收山断口；相邻面先协商共享细分，再生成内部采样，消除 T 形接缝。
- 瓦面相邻列建立公共参数断点集合；对每个单元按其屋面域裁切。不能继续假定不同长度列的第 k 点属于同一横排。
- `tile_coverage` 改为从脊向檐的固定归一化屋面参数区间，并插入准确边界；不再通过采样点数取整。覆盖率变化只改变覆盖范围，不重新拟合屋面。
- 扫掠位移新增稳定曲线参数输入；Legacy 保留节点序号模式。V2 位移使用选定且固定的母线参数或归一化弧长，不能在各 LOD 中重新按节点序号分配。
- 回归已有 miter 退化保护与位移约束；对不必要的尖角保留硬转折，对曲面使用平滑法线，不一律抹平。

**验收门槛**：固定结构切换质量档时，关键定位点差异 ≤0.1mm；近景采样相对独立高精度参考的最大距离 ≤选定误差；共享接缝位置差异 ≤0.1mm。旧模式几何回归一致；覆盖率和扫掠位移不随细分漂移。截图用于评审，不要求整图零差。

### P2：稳定构件标识、柱面与真实边缘细节

**依据**：H §4.1 提供层次描述思想；法线、倒角、稳定哈希为工程方案。

**改动位置**：`BuildingBuilder.h/.cpp`、`TileSkin.h/.cpp`；拟新增轻量 `BuildingComponentRecord`。

任务：

- 在现有构件生成入口传入稳定 ID 与 MaterialClass。首先覆盖柱、梁、墙、台基、斗拱、屋面分区、瓦垄，暂不重写全部层级生成器。
- 柱侧面按端点角输出解析法线。对高度 H、底半径 r0、顶半径 r1 的圆台，侧法线可取 `normalize(cosθ, (r0-r1)/H, sinθ)`；端盖若可见则独立硬法线。
- 新增可选局部倒角原语，先作用于柱础、台阶前缘和梁头；倒角宽度受构件最小尺寸约束，质量切换不得改变母体尺寸。
- 柱础以半径-高度剖面回转，复用网格累积设施；不要让建筑核心依赖编辑器节点实例。
- 色差取 `Hash(seed, semantic_component_id)`，同一构件各面一致；瓦片先保留低幅度变化，不未经视觉比较统一减半。
- 数据相同的顶点可按位置、法线、UV、颜色、材质/其他属性完整组合去重；保留硬边、UV 接缝。先统计收益，再决定是否加入此阶段。

**验收门槛**：柱面侧光连续，轮廓精度与质量档一致；倒角实际出现在轮廓/深度输出中；相同构件 ID 在改变细分、关闭其他部件及跨 LOD 时色差不变。参数变化造成真正构件增删时允许局部 ID 集合变化。

### P3：檐下结构与四类材质，完成首个可评审样板

**依据**：H §4.2 的 subspline/椽生成；檐口具体断面、材质参数为本项目方案。

**改动位置**：`BuildingBuilder.cpp`、`PolygonalBuilding.cpp`、`AncientBuilding.cpp`、`AncientBuildingParameters.h/.cpp`；拟新增 `EaveStructure.h/.cpp` 与建筑材质资源。

**P3.1 檐下结构**

- 先做歇山：椽头→飞椽→连檐板衔接→柱头斗拱剪影，使用共同屋面局部坐标与檐口断面。
- 椽距独立设置，默认约 0.34m 仅为样板调试值；与瓦垄可以对齐但不硬绑定。定义椽子与望板、檐板的相对层位，避免只在最外沿贴一圈短柱。
- 飞椽长度、断面、倾角由断面参数给出；不能固定“在望板上抬一皮”解决所有屋型。验收用剖面调试显示确认承托和穿插关系。
- 翼角区沿局部切向/法向布置并逐步过渡；转角构件单独识别，不能把正面斗拱简单旋转后在角部重复叠放。
- 斗拱先改善拱臂下缘和逐级出挑剪影；榫卯内部不进入第一轮。普通样板先有清楚层次，再按实测决定补间铺作密度。

**P3.2 材质数据闭环**

- 第一版分 `Timber/Tile/Plaster/Stone` 四个 surface/material 槽。灰脊归 Tile 类起步；额外材质通过记录扩展，不靠颜色猜材质类型。
- 先使用可诊断的标准材质验证：四类不同粗糙度，普通材质 metallic=0；随后替换为项目 NPR 兼容材质，保持槽与数据契约。
- UV 采用米制尺度；柱/梁顺长轴，墙面按局部平面，瓦面按沿坡弧长与横向瓦垄坐标。需统一 UV 手性与方向。
- 切线依据最终位置、法线及 UV 生成，正交化并输出四分量与手性。镜像 UV、UV 接缝、退化 UV 必须有定义，不把“沿坡向”无条件当切线。
- 首版无纹理也能显示四类材质；贴图输入可选。单独用棋盘格与法线调试图验证，4K 贴图本身不是 UV 验收标准。
- 修正 `spawn_meshes.gd` 的实例颜色路径：为建筑材质保留 surface 材质，通过兼容材质接收实例颜色；旧通用节点的行为通过显式设置保持兼容，不能全局悄悄换材质策略。

**验收门槛**：檐下机位可辨连续椽头、飞椽和斗拱层次；望板不漏光；单体与 PCG 实例色开启/关闭均保留四类响应；法线贴图方向、镜像手性正确。记录新增 surfaces、draw calls、三角形与帧时间成本。

### P4：近景瓦片搭接与脊边裁切

**依据**：H §3.2、§4.2、§6.3；瓦片尺寸、搭接网格和裁切域为工程实现。

**改动位置**：`TileSkin.h/.cpp`、各屋型瓦列生成入口、屋面边界记录。

任务：

- 新增 `ContinuousSkin` 与 `LappedTiles` 两种表现，共用同一屋面、瓦宽、瓦长和物理排号。
- `tile_length` 初值 0.35m、`overlap_length` 初值 0.08m，排距为两者之差；强制 `0 ≤ overlap < length`。瓦唇高度从 0.01m 起调，不能当所有建筑的历史规格。
- 沿稳定母线弧长布局；瓦片自檐口向上编号，上排下缘覆盖下排上缘。真实搭接边要有窄立面或厚度，避免只有抬高顶点造成缝隙。
- 筒瓦、板瓦允许不同排相位，但同一截面单元必须共享连接参数。瓦当/滴水只在实际檐口生成；卷棚保留两端规则，歇山上部断口不误加滴水。
- 正脊、戗脊、收山断口建立明确终止域与遮盖余量。直线边界可用半空间裁切，曲线边界用分段边界/参数域裁切；一条高度函数不能代表全部接合情况。
- 末片允许裁短并在脊盖下隐藏切口；不强制“最后一排保持完整”而导致穿模。新产生的可见切口需要封边。
- 预算上限触发时切换到连续瓦面，保存相同瓦片尺度与颜色定位。编辑预览可使用低档，最终烘焙重新生成选定档位。
- 集中式屋顶先保留现有顶冠覆盖策略；分区收垄作为独立质量项，避免把顶部细线问题和九型全面改造绑在一起。

**验收门槛**：侧光与掠射角可见搭接节奏，檐口构件不重复；0/部分/全覆盖正确；大瓦宽 2m 为极端鲁棒性案例而非默认美术尺度。正脊/翼角无可见穿出、开放裂缝或 z-fighting；质量降档不把瓦片放大。

### P5：九型 PCG、静态 LOD、缓存与空间分块

**依据**：H §5 的分层简化思想；具体采用静态烘焙与 Godot 资源实例化是工程选择。

**改动位置**：`AncientBuilding.cpp`、参数/编辑器插件、`ancient_building.gd` / `ancient_building_settings.gd`；拟新增建筑烘焙资源与建筑专用分块实例器。

**P5.1 九型参数贯通**

- 同步 PCG 枚举、`ROOF_TYPE_COUNT`、标题、随机屋型池和完整参数透传；集中式/脊式的合法参数由共用解析器处理。
- PCG 接受参数预设资源及显式覆盖，避免在 GDScript 重复维护全部 C++ 默认值。明确风格预设与手工颜色的优先级，检查现有先设风格后覆盖颜色的流程。
- 有稳定 point seed/ID 时优先据此选择变体；缺失时保留按序号选择的兼容回退。移动/增加无关点不应让全村变体重排。
- 新功能先覆盖歇山，再扩展其余家族；九型入口接通不等于九型高质量已验收，须分别标记能力。

**P5.2 三档表现**

| 档位 | 几何表现 | 保持不变的内容 |
|---|---|---|
| LOD0 | 搭接瓦、完整檐下细节、局部真实倒角 | 母线、主要剪影、物理构件尺寸与语义 ID |
| LOD1 | 连续瓦面、保留主要檐口，简化斗拱/椽头 | 建筑尺度、主要脊檐轮廓、材质与瓦片节奏 |
| LOD2 | 封闭屋面与主体大形、少量主要脊线；瓦纹可转为材质表达 | 建筑识别性、色块与远景阴影轮廓 |

- 结构与材质表达不同，首选三个独立 Mesh。仅对拓扑/材质兼容的局部减面使用 ArrayMesh 索引 LOD；本地引擎 `mesh.h` 已提供 LOD 字典接口。
- 不在运行时随相机距离调用建筑 Generate。先按屏幕投影误差选择阈值，加入约 10% 的滞回区作为调试起点，再用移动路径测试调优。
- MultiMesh 按 `(空间块, 变体, LOD, 材质配置)` 管理；40 屋案例先用小组/街区分块。逐实例选档需移入相应档位的实例缓冲，或以小块统一切换；不可声称单个 visibility_range 能分别切换一个 MultiMesh 内每栋建筑。
- 替换细节与主体使用一致档位/过渡策略；同步验证阴影，避免主体消失而细节仍在。
- Billboard 与构件贴片不是首轮必需。仅在 LOD2 仍超预算时再评估多视角代理、透明开销、阴影和 NPR 一致性。

**P5.3 缓存与交付**

- 缓存键包括生成器版本、解析后的结构/造型/尺寸、稳定 seed、质量档、材质/原型依赖版本。
- 区分几何缓存与材质实例：只改颜色或粗糙度不重新生成顶点；只改屋顶不使无关台基缓存失效。先分 Base/Body/Roof，再细化。
- 延迟合并同一帧参数变化；统计冷生成、热命中、加载烘焙资源三种路径。持久化资源写入专门生成目录，参数源始终保留。
- 对缓存设置容量/失效策略；多个质量档、精品构件和纹理都计入内存，不能以“缓存全部结果”作为无限制方案。
- 现有 `bake_mesh()` 返回默认档；新增烘焙包接口提供多档资源，旧 `spawn_meshes` 路径继续可用。
- 独立碰撞体按游戏需求生成简化代理；不直接将瓦片/斗拱细节网格变为复杂碰撞。

**验收门槛**：九型参数合法、保存重开一致；4 个变体不按 40 个实例重复烘焙；相机运动不会触发几何重建；跨块/跨档无明显跳变或资源泄漏；实例色和 NPR 材质不失效。

### P6：精品构件替换、重檐和多层主体

**依据**：H §4.1 层次树与构件局部 frame；Q 的高等级组合需要真实能力支持。

- 首批替换斗拱、瓦当、脊端装饰、门窗。记录 `id/type/parent_id/local_transform/dimensions/material_class/prototype_id`，另存替换资源映射；bitmask 只表示启用集合，不能代替资源映射。
- 原型约定原点、前向、上向、连接点、名义尺寸及允许缩放轴；替换时禁用对应默认构件，缺资源时回退程序构件。
- 默认按变体把替换后的构件合并进各材质 surface，继续兼容现有 Mesh 资源流。确需独立实例化的重复构件由专用建筑实例器管理，不能让一个仅输出 Mesh 的 PCG 节点暗中挂出不可追踪节点。
- 重檐使用 `RoofTierSpec` 描述上下檐、平面退缩、檐间带及承托关系；多楼层使用独立 `StoreySpec`。两者允许组合但不互相等同。
- 处理下层屋面内侧开口、上部支承、重叠区域、材质与 LOD 连接。完成后才启用含重檐的等级预设。

**验收门槛**：替换可逆、无重复旧构件、连接点位置正确，单体与 PCG 输出一致；重檐剖面连续且有合理承托；缺少能力的预设报告原因而非静默冒充实现。

### P7：用途预设与城市布局研究（后续范围）

- 先建立“民居/厅堂/亭/楼阁/廊”等用途预设，分开屋顶类型、主体类型、层数、材料风格、地域/时代参考来源。
- Q 表 7 可实现为可选的 `Qin2023Demo` 组合规则集。缺失部位等级按论文组合思想解析；当前不能生成的重檐/塔式组合标记未支持，不能映射到随意相近类型。
- 明清或地域预设必须补充具体测绘、实物/构造图参考，再确定参数；X 的计数只用于资料说明，不作为几何参数依据。
- 后续城市层将位置/用途/地块约束输出为建筑参数，不把道路 L-System 放进单体生成器。Q 自述缺少用户引导，因此应预留主轴、道路、功能区、禁建区、战斗空间等人工约束。
- 若复现 Q 位置函数，应定义城市局部坐标与尺度、中心除零保护、连续等级到离散参数的取整、噪声越界处理。式 10 在明确范数前不实现；正交旋转不会改变二范数，不能仅靠“旋转 45°”声称得到方形等级区。

## 6. 验收矩阵与性能口径

### 6.1 功能与几何

每项测试针对实际风险，不要求每次改文档或调整颜色都运行完整矩阵。

| 组别 | 覆盖项 | 检查 |
|---|---|---|
| 兼容 | 原参数、新字段缺失、显式高度、保存重开 | 旧模式结构不变；无隐式迁移写坏资源 |
| 九型 | 全九屋顶；集中式 4/8 边及圆形分支 | 有限坐标、合法索引、法线方向、正体积范围 |
| 屋面 | 各质量档、强翼角、卷棚顶、低/高坡度 | 误差、接缝、位移稳定、绕序与厚度 |
| 瓦片 | 覆盖率 0/0.4/1、正常/极大瓦宽、末排裁切 | 无漏缝/穿出；仅实际檐口有瓦当/滴水 |
| 材质 | 标准/NPR、实例色开关、镜像 UV | 分类正确、棋盘格尺度、切线手性 |
| 确定性 | 改精度、改 LOD、关闭邻近构件、点顺序变化 | 同一语义 ID 的颜色/定位稳定 |
| 批量 | 单栋、40 实例/4 变体、运动路径 | 缓存命中、分块剔除、档位切换、加载 |
| 可选能力 | 替换缺失、重檐、多层 | 回退清晰；构造和资源生命周期正确 |

### 6.2 性能

- 记录目标机器、CPU/GPU、分辨率、D3D12、阴影和 AA。预览与发布构建分别记录；无头运行只能验证数据和功能，不能替代 GPU 性能验收。
- 固定路径预热后采集至少 30 秒，报告 CPU/GPU 与总帧时间的中位数/P95，同时记录可见三角形、draw calls、显存/缓存和最大尖峰。
- 60 FPS 对应总帧时间目标约 16.67ms；CPU 与 GPU 通常重叠执行，不简单相加。单独建筑场景达标不等于含战斗、特效的完整游戏达标。
- 原项目加载 <3s 目标保留，P0 后明确是完整场景冷加载还是热加载；分别测量。单栋生成 <1s 可作为临时上限，编辑器交互还需测主线程停顿，不能用平均值掩盖卡顿。
- 三角形比例和距离阈值在 P0/P3/P4 实测后锁定；不承诺复现论文 1/35 减面或论文 FPS。若质量样板超预算，先减少不可见面/次要细节并改进 LOD，不能把近景 45 FPS 标记为通过。

### 6.3 每阶段交付物

1. 变更说明：解决问题、涉及接口、兼容策略、剩余限制。
2. 参数预设与可复现场景；三个固定机位前后图，几何相关阶段增加法线/线框/深度检查。
3. 统计表：按部件的面数/材质槽、生成/提交耗时、CPU/GPU 帧时间、缓存容量。
4. 与本阶段风险直接相关的自动断言；视觉评审单独记录，不以“网格非空”代替视觉通过。

### 7.1 城镇 PCG 完成记录 (2026-09-26)

Ancient Building PCG 已用于搭建中大型古代城镇（城市/市集/村镇/聚落四类聚落，见 `Game/addons/ancient_town/` 与 `Game/Map/Map_AncientTown.gd`，五预设截图在 `Reference/Shots/AncientTown/`）。

关键缺陷记录（本轮修复）：

- **道路/城墙不渲染**：`flow_data.gd` `TransformsStream.atIndex()` 用 `basis.scaled(size)` 构造变换，即 `S·R`（沿世界轴缩放）。对 yaw≈90° 的非均匀缩放实例（道路条带 size=(len,0.1,width)），长度与宽度在世界轴互换了位置：条带被渲染成垂直于路线的宽横带，御道在机位画面中完全不可见；MMI 包围盒也因此错乱（此前观察到道路 MMI aabb 为 P(-514,0,-259) S(1028,0.12,518) 的镜像翻倍盒，即源于此）。渲染器、墨色材质、描边、剔除均被逐一排除（黑地探针 + 品红无光材质对照组 C1–C5），最终定位在变换组合约定。
- **修复**：改为 `Transform3D(basis, pos).scaled_local(size)`，即 `R·S`（沿旋转后的局部轴缩放），与 `node_draw_debug.gd` 既有的 `scaled_local` 语义一致，也与引擎 fork 的 `M=R·S` 分解约定（`get_scale()` 返回列长）一致。均匀缩放与单位尺寸实例（树/建筑/道具）不受影响，语义变更安全。
- **验证**：修复后道路 MMI aabb 恢复正常（P(-260,0,-260) S(520,0.12,520)）；五个预设（city/village/market/hamlet/all）16 张截图全部重拍通过，城市御道宽度经鸟瞰像素量测（城墙环 ±256 定标，≈1.1px/单位）确认为 16 单位全宽，街道网格、城墙、建筑、树在四类聚落中均正常渲染。

遗留与边界：hamlet 斜向巷道在旧语义下长宽失真，修复后一并正确；墨色纸底观感（白色地面）属风格预期，远景雾/景深参数已按臂长自适应，后续视觉评审再定稿。
